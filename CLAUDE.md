## Commands

- `pnpm dev` — dev server at http://localhost:3000
- `pnpm build` — production build (also the closest thing to a type-check; there is no separate `tsc` script)
- `pnpm lint` — ESLint (flat config in `eslint.config.mjs`, Next core-web-vitals + TypeScript rules); lint one file with `pnpm exec eslint app/content.ts`

- `node scripts/scrape-magnor.mjs` — re-scrapes Magnor Midtun's original site with Playwright and overwrites `content/archive/` and `public/archive/`. Only run it when asked to refresh the source material. It leaves `content/archive/en/` alone, but the English translations are keyed by block index, so check them against any page whose blocks changed.

There is no test framework set up yet.

## Architecture

The site republishes a scraped local-history archive in Nynorsk (default) and English. Content comes from two layers that are joined by chapter number:

- **Editorial layer — `app/content.ts` and `app/content-en.ts`.** Hand-written: `siteUrl`/`siteName`/`author`, the four `temaer`, each with its `kapitler` (`number`, title, URL `slug`), plus hero and page copy. `content.ts` exports the Nynorsk `nnContent`; `content-en.ts` builds `enContent` from it with the same shape (`SiteContent`), so slugs and numbers stay shared. `kapitler` is the flattened list that drives routing, prev/next navigation and the sitemap. Adding or renaming a chapter starts in `content.ts`, then add its English title and description in `content-en.ts`.
- **UI strings — `app/dictionary.ts`.** Every interface string (navigation, breadcrumbs, labels, 404 text, OG card text) per locale. `getDictionary(locale)` and `getContent(locale)` are the entry points for components.
- **Source layer — `content/archive/`.** Generated by the scraper: `manifest.json` lists every scraped page with its `chapterNumber` and JSON file under `pages/`. Each page is a list of typed blocks (heading, paragraph, listItem, image). `raw/`, `screenshots/` and `REPORT.md` are reference material only. Images are served from `public/archive/kapNN/`.
- **Translations — `content/archive/en/<slug>.json`.** `{ "blocks": { "<index>": "text" } }`, keyed by the index of the Nynorsk block (for image blocks the text is the caption). Blocks without an entry fall back to Nynorsk, and a page without a file is shown in Nynorsk with a notice. Written-work titles in English are sentence case and used as-is.
- **Loader — `app/archive.ts`.** Server-only (`node:fs`). It reads from the filesystem at build time. `getKapittelPages(number, locale)` returns a chapter's main page plus sub-pages in manifest order, with `language` set to the language actually shown. Helpers derive the meta description, the first image (for OG) and in-page section anchors. Sections normally come from headings; `kapittelSections` holds hand-picked overrides with titles per locale. Written works (chapters 23–27) are parsed from the Nynorsk text so ids, titles and metadata detection stay stable, and the English text is swapped in line by line.
- **Locales — `app/i18n.ts` and `app/locale.ts`.** `locales`, `defaultLocale`, `localePath`, `stripLocale`, `languageAlternates` and `ogLocales` are client-safe. Server components read the current locale with `getLocale()` (from `next/root-params`).
- **Routes.** Everything lives under the root segment `app/[lang]/` (`nn`, `en`; `dynamicParams = false`). `next.config.ts` rewrites unprefixed paths to `/nn/...`, so Nynorsk keeps its root URLs and English lives under `/en` with the same slugs; `/nn/...` redirects to the unprefixed URL. Pages: `/` (composition of section components), `/kapittel` (index), `/kapittel/[slug]` (statically generated from `kapitler`, unknown slugs 404), `/dikt-og-tekstar`, `/kart`, `/om-oss`. The site root and each chapter and written work also have an `opengraph-image.tsx` built from the shared `OgCard` component. There is no root layout outside `[lang]`, so unmatched URLs render the bilingual `app/global-not-found.tsx`. `sitemap.ts` and `robots.ts` derive from `content.ts` and list both locales.

Components import the modules they need with relative paths (`../../archive`), not `@/`. Links inside the site go through `localePath(locale, path)`.

## Stack

- Next.js 16.3 (App Router only, in `app/`, all routes under `app/[lang]/`), React 19.2, TypeScript strict. Next 16 differs from older versions — check `node_modules/next/dist/docs/` (`01-app/`, `03-architecture/`) before relying on remembered APIs. For example, `app/[lang]/layout.tsx` uses the globally generated `LayoutProps<"/[lang]">` type helper rather than hand-written props types.
- Styling is plain CSS in `app/globals.css`, using the color variables defined there. No Tailwind classes or external font loading. `tailwindcss` and `postcss.config.mjs` are leftover scaffold and are not imported by `globals.css`.
- Import alias `@/*` maps to the repo root.

## Notes

- `AGENTS.md` is written and re-added by `next dev`; don't remove its block. Keep project guidance in this file and the detailed architecture rules in `.claude/skills/webarkitektur/SKILL.md`.
- Naming: domain words in code are Bokmål (`Tema`, `Kapittel`, `Arkiv`; plurals `temaer`, `kapitler`); everything else — folders, files, technical names, props, CSS classes, comments — is English (`TemaCard`, `KapittelGroup`, `Header`, `.section-heading`). User-facing copy is content: Nynorsk by default (`lang="nn"`), with English copy in `content-en.ts`, `dictionary.ts` and `content/archive/en/`. URL slugs and anchors stay Nynorsk in both languages.
- Keep page data in `app/content.ts` and shared page components directly in `app/components/`. Keep `app/[lang]/page.tsx` as a readable composition; avoid extra directory layers and barrel files.
- Server Components are the default. Add a client boundary only for UI that needs state, event handlers, or browser APIs. Use composition instead of boolean props to select different layouts.
- In Next.js 16, use `preload` when a `next/image` asset must be preloaded; `priority` is deprecated.
- Route feedback lives in `app/[lang]/error.tsx`, `app/[lang]/not-found.tsx` and `app/global-not-found.tsx`. Keep messages in both Nynorsk and English and follow the installed Next.js file conventions. Keep archive content visible in the initial HTML without JavaScript; a root `app/[lang]/loading.tsx` can leave the static content hidden behind its fallback for clients without JavaScript.
- SEO rules (metadata, sitemap, OG images, JSON-LD, verification) live in `.claude/skills/seo/SKILL.md`; follow it when adding routes or content.
- Keep the README specific to this archive. Remove unused starter assets and empty configuration files instead of carrying generic scaffold content forward.
